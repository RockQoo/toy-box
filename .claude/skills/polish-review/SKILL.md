# 연출 / 완성도 검토

현재 게임을 **상용 모바일/PC 게임의 완성도 기준**으로 검토한다. 대상은 **어린아이가 부모와 함께 하는 미니게임 모음**이다.
새 콘텐츠나 기능을 추가하는 것보다, **이미 있는 게임플레이가 충분히 전달되지 않거나 완성도를 떨어뜨리는 요소**를 먼저 찾는다.

목표는 더 화려하게 만드는 것이 아니다. **의도가 명확하고 일관되며, 아이가 행동의 원인과 결과를 즉시 이해할 수 있는 상태**가 목표다.
효과를 많이 넣지 않는다. 이 게임에서 체감 효과가 큰 것만 제안하고, 불필요하거나 과한 효과는 뺀다.

## 진행 방식

1. 코드(`scripts/Games/<게임>/`, `scripts/Common/`, `scripts/Core/`)를 읽고 실제 화면을 확인한다.
   - `--write-movie <스크래치 경로>/f.png --fixed-fps 30 --quit-after N -- --game=<id> --autoplay`로 프레임과 `.wav`를 뽑아 본다.
   - 추측으로 평가하지 않는다. 구현 여부는 코드에서 확인한 것만 적는다.
2. **검토만 하고 코드는 수정하지 않는다.** 결과를 보고한 뒤 사용자가 고른 항목만 구현한다.
3. 결과는 한글로 작성한다.

## 1. 사건 파악과 흐름 분석

먼저 검토 대상 게임의 중요한 사건과 상호작용을 목록으로 만든다. 모든 게임에서 공통으로 다음을 본다.
메인 메뉴 진입, 게임 카드 선택, 꾸미기(옵션 선택), 시작 버튼, 3초 카운트다운, 게임 시작, 핵심 행동(터뜨리기, 받기, 뒤집기, 이동, 정답 선택, 점프), 성공, 실패/놓침, 난이도 상승, 남은 시간 경고, 게임 종료, 결과 화면, 점수 count-up, 최고 기록 갱신, Top 10 이름 입력, 랭킹 표시, 다시 하기, 메인으로.

각 사건을 다음 흐름으로 분석한다.

> 입력 → Anticipation(준비) → 행동 → 충돌/변화 → 결과 → Recovery/정착

**로직은 있지만 표현이 부족한 사건**을 우선 찾는다. 예:
- 터뜨렸지만 터졌다는 느낌이 약하다
- 버튼은 작동하지만 눌렀다는 반응이 없다
- 점수는 오르지만 숫자만 바뀐다
- 게임은 끝나지만 감정적인 마침표가 없다
- 랭킹에 들었지만 축하받는 느낌이 없다

## 2. 확인할 요소

각 요소마다 **현재 구현 여부 / 문제점 / 개선 효과 / 구현 난이도 / 우선순위**를 평가한다.

- 입력 직후의 시각, 청각, 햅틱 피드백
- Tween, Lerp, Easing을 활용한 움직임과 수치 변화
- Anticipation, Squash & Stretch, Follow-through, Secondary Motion
- Hit Flash, Screen Shake 등 타격 피드백(아이용이므로 과하지 않게)
- Particle, Trail, Impact 등 시각 효과
- Count-up 등 상태 변화 표현
- 등장, 획득, 사라짐 과정
- 화면 전환, 결과 화면, 최고 기록, 랭킹 연출
- 버튼의 Press, Release, Disabled 상태(터치 기기에서 의미 없는 Hover는 제외)
- 정보 위계와 UI 가독성. **글을 잘 못 읽는 아이도 그림과 소리만으로 이해할 수 있는지**
- 터치 영역 크기(아이 손가락 기준), 잘못 누르기 쉬운 배치
- UI와 게임 오브젝트의 등장, 퇴장 타이밍
- 사운드와 화면 효과의 동기화
- 모바일 Haptic Feedback의 적절성
- 반복 플레이 때 지나치게 길거나 지루해지는 연출
- 여러 효과가 같은 정보를 중복 전달하거나 서로 시선을 방해하는 문제
- **실패감을 주는 표현이 없는지**(감점, 붉은 경고, 큰 실패음은 피한다. `docs/GDD.md` 원칙)

## 3. 연출 강도의 위계

각 사건의 **게임플레이 중요도에 비례해** 연출 강도를 정한다. 모든 사건에 같은 수준의 Screen Shake, Particle, Sound를 적용하지 않는다.

- **일반 행동**: 풍선 하나 터뜨리기, 과일 하나 받기, 카드 뒤집기, 한 칸 이동. 자주 일어나므로 짧고 가볍게, 시선을 빼앗지 않게 한다.
- **중요한 행동**: 연속 성공, 10개 단위 달성, 짝 맞추기 성공, 정답, 별 획득, 난이도 상승.
- **클라이맥스**: 게임 종료, 최고 기록 갱신, Top 10 진입, 모든 짝 완성, 미로 탈출.

중요한 시퀀스는 개별 효과가 아니라 **연속된 경험**으로 검토한다.
예: 마지막 행동 → 종료 알림 → 짧은 여운 → 결과 count-up → 최고 기록/랭킹 축하 → 다음 행동 안내.
반복 플레이를 방해할 만큼 길어지지 않게 설계한다(다시 하기까지 걸리는 시간도 함께 본다).

## 4. 정리 대상

현재 프로젝트에서 다음을 찾아 **유지 / 통합 / 삭제** 중 하나를 제안한다.
- 중복된 연출
- 중복된 코드(공통 시스템 `scripts/Common/`로 옮길 수 있는 것)
- 사용하지 않는 기능
- 역할이 겹치는 UI
- 게임마다 스타일이 다른 요소(폰트 크기, 색, 외곽선, 버튼 모양, 애니메이션 곡선 등)

## 5. 결과 정리

제안 전체를 다음 순서로 정리한다.

1. **즉시 수정하면 효과가 큰 것**
2. **적은 비용으로 개선 가능한 것**
3. **나중에 다듬을 디테일**

각 항목에는 관련 파일과 위치(`파일:줄`)를 붙인다.
